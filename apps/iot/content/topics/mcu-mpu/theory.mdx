## Idea

Todo nodo IoT necesita "un cerebro" que lea sensores, tome decisiones y hable con el resto
del sistema. Ese cerebro es un microcontrolador (MCU) o un microprocesador (MPU), y la
diferencia entre ambos —qué traen integrado, cómo acceden a la memoria y qué tan rápido
ejecutan— determina en qué capa de la arquitectura IoT aparece cada uno: el MCU vive dentro
del nodo sensor/actuador; el MPU aparece donde se necesita cómputo general (gateway,
smartphone, servidor).

## Conceptos

### Arquitectura Von Neumann vs Harvard

La forma en que la CPU accede a memoria de datos y de instrucciones define dos familias de
arquitectura:

| Aspecto | Arquitectura Von Neumann | Arquitectura Harvard |
|---|---|---|
| Memoria | Compartida para datos e instrucciones | Separada para datos e instrucciones |
| Buses de datos | Un solo bus para instrucciones y datos | Buses separados de datos e instrucciones |
| Desempeño | Más lento (memoria y bus compartidos) | Más rápido (rutas de datos en paralelo) |
| Complejidad | Más simple, menor costo | Más compleja, mayor costo |
| Ejemplos | Computadoras de propósito general, PCs, sistemas embebidos | DSP (Digital Signal Processors), microcontroladores (ej. ARM Cortex) |

### CISC vs RISC

Clasificación por el tipo de conjunto de instrucciones que ejecuta la CPU:

| | CISC (Complex Instruction Set Computer) | RISC (Reduced Instruction Set Computer) |
|---|---|---|
| Ciclos de reloj | Muchos ciclos por instrucción | Un ciclo por instrucción |
| Uso de memoria | Mejor aprovechamiento de la RAM (instrucciones más "densas") | Acceso intenso a RAM (instrucciones simples y frecuentes) |
| Ejemplos | AMD y Intel x86 | ARM y SPARC |

### Microprocesador (MPU) vs microcontrolador (MCU)

En 1971 aparecen los dos hitos que fijan esta distinción: el **Intel 4004** (microprocesador,
arquitectura Von Neumann, necesita memoria e I/O externos) y el **TMS 1000** (microcontrolador,
concepto de "computadora en un chip", arquitectura Harvard, con memoria e I/O integrados para
sistemas embebidos).

| Aspecto | Microprocesador (MPU) | Microcontrolador (MCU) |
|---|---|---|
| Definición | Solo CPU; necesita componentes externos (RAM, ROM, I/O) | Sistema completo en un chip (CPU + RAM + ROM + I/O) |
| Integración | Baja (solo la CPU adentro) | Alta (CPU, memoria y periféricos adentro) |
| Uso principal | Cómputo complejo (PCs, servidores) | Sistemas embebidos (electrodomésticos, robots) |
| Consumo de energía | Mayor | Menor |
| Capacidad de proceso | Alta velocidad, multitarea potente | Velocidad moderada, optimizada para control |
| Gestión de memoria | RAM/ROM externas | RAM/ROM internas |
| Costo | Más caro | Más barato |
| Ejemplos típicos | Intel Core i7, AMD Ryzen | ATmega328P (Arduino), STM32, ESP32 |
| Complejidad de programación | Sistemas operativos complejos (Linux, Windows) | Firmware simple o RTOS |

**Ejemplos de microprocesadores**: Intel Quark SoC, Broadcom BCM2835, ARM11, Cortex A20 (los
pines de estas placas vienen soldados, pensados para desarrollo).

**Ejemplos de microcontroladores**: Arduino, Atmel AVR, PIC (Microchip Technology).

### Pines comunes de un microcontrolador

| Pin | Nombre | Función |
|---|---|---|
| Vin | Voltage in | Voltaje de entrada / alimentación |
| GND | Ground | Tierra / referencia de 0 V |
| RST | Reset | Reinicia el programa en ejecución |
| CLK | Clock | Señal de reloj del sistema |
| TX | Transmit | Transmisión de datos serial |
| GPIO | General Purpose Input/Output | Pin digital configurable como entrada o salida |
| I2C | Inter-Integrated Circuit | Bus serial de dos hilos (SDA/SCL) para comunicarse con periféricos |

### Dónde aparecen en la arquitectura IoT

La arquitectura general de un sistema IoT se puede ver como un embudo: *Things* (los
dispositivos físicos) → *Local network* → *Global network* → *Cloud service* → *Controlling
device*. El MCU vive **dentro del "Thing"**: es el chip que lee sensores y acciona salidas en
el nodo embebido. El MPU aparece donde se necesita cómputo general: un gateway tipo Raspberry
Pi en la red local, o el smartphone/servidor que hace de "controlling device" y de nube.

## Método paso a paso

Para decidir si un chip dado es MCU o MPU (y dónde ubicarlo en un diagrama de arquitectura):

1. **¿Trae memoria e I/O integrados, o los necesita externos?** Integrados → MCU. Externos
   (necesita RAM/ROM/I/O aparte) → MPU.
2. **¿Para qué se usa?** Control embebido de un proceso acotado (leer sensores, mover un
   motor) → MCU. Cómputo de propósito general (SO completo, multitarea) → MPU.
3. **¿Qué arquitectura de memoria usa?** Harvard (buses separados, típico de control en
   tiempo real) → suele ser MCU. Von Neumann (bus compartido) → suele ser MPU o DSP.
4. **¿Dónde se ubicaría en la arquitectura IoT?** Si va soldado al nodo sensor/actuador →
   capa *Things*, es el MCU del sistema. Si es la placa que agrega, procesa o reenvía datos de
   varios nodos → capa *Local/Global network* o *Cloud*, es un MPU.

## Ejemplo resuelto

Un **Arduino Uno** (ATmega328P) controla un sensor de humedad y un motor DC; una **Raspberry
Pi 4** recibe esos datos por Wi-Fi y los sube a la nube.

- ATmega328P: memoria y periféricos integrados en un solo chip, arquitectura Harvard,
  firmware simple sin sistema operativo → es un **MCU**. En la arquitectura IoT ocupa la capa
  *Things* (dentro del nodo agrícola).
- Raspberry Pi 4 (Broadcom BCM2835/2711): necesita memoria RAM externa y corre Linux
  (sistema operativo completo, multitarea) → es un **MPU**. En la arquitectura ocupa la capa
  *Local network* (gateway) o *Controlling device*, según el rol que cumpla.

## Errores típicos

- Confundir "microcontrolador" con "placa de desarrollo": el Arduino Uno es una placa; el
  MCU es el chip ATmega328P soldado en ella.
- Pensar que RISC siempre es "más simple de programar": RISC reduce el hardware de
  decodificación, pero exige más instrucciones (más accesos a RAM) para lograr lo mismo que
  una instrucción CISC.
- Asumir que todo lo que está "adentro del gateway" es un MCU: un gateway (p. ej. Raspberry
  Pi) suele llevar un MPU corriendo Linux, no un MCU.
- Olvidar que Harvard no es "sin memoria compartida en absoluto": lo que se separa son los
  buses de instrucciones y datos, no necesariamente los chips físicos de memoria.
