## Idea
MQTT define quién habla con quién (broker, publisher, subscriber) y cómo se empaqueta
cada mensaje sobre TCP. El paquete siempre tiene la misma forma — header fijo, largo
restante, header variable, payload — sin importar si es un CONNECT o un PUBLISH; lo único
que cambia es el contenido de las dos últimas partes.

## Conceptos

### Roles
- **Broker**: puede vivir en el gateway local o en la nube. Recibe todo, decide a quién
  reenviar o qué procesar.
- **Publisher**: se conecta al broker para publicar datos. No programa el mensaje hacia
  un cliente específico, sólo lo clasifica en un tópico.
- **Subscriber**: dispositivo, app o servicio que necesita el dato. Se conecta al broker
  para que le avisen cuando algo nuevo llegue a los tópicos que le interesan.

MQTT es **data agnostic**: no interpreta el payload, sólo lo transporta. Corre sobre TCP
(puerto 1883 en claro, 8883 con TLS — ver [Tópicos y seguridad](/topics/mqtt/subtopics/topicos-y-seguridad)).
No hace falta conocer la implementación de TCP, basta con el paradigma header→payload.

### Fixed header (2+ bytes)
Todo paquete MQTT empieza con este header fijo de al menos 2 bytes:

| Byte | Bits 7-4 | Bit 3 | Bits 2-1 | Bit 0 |
|---|---|---|---|---|
| Byte 1 | Message Type (4 bits) | DUP | QoS Level (2 bits) | RETAIN |
| Byte 2 | Remaining Length (1 a 4 bytes) | | | |

- **Message Type**: 4 bits → hasta 16 tipos de paquete (ver tabla abajo).
- **DUP** (Duplicate Delivery Flag): 1 si este PUBLISH es una retransmisión.
- **QoS**: 2 bits → nivel 0, 1 o 2 (ver [QoS](/topics/mqtt/subtopics/qos)).
- **RETAIN**: 1 si el broker debe guardar este PUBLISH como el último valor del tópico.

### Remaining Length
Especifica cuántos bytes siguen después de este campo: header variable + payload. El
largo total del paquete = tamaño del fixed header + Remaining Length.

### Message types (los tres que vio el curso; el resto queda como referencia)
- **CONNECT**: crea la conexión con el broker y espera a que se establezca.
- **DISCONNECT**: espera a que el cliente termine su acción y cierra la conexión TCP/IP
  (deja de escuchar).
- **PUBLISH**: transporta el dato enviado por el cliente MQTT.

> **Nota de apoyo** (no está en el material, pero forma parte de la tabla oficial de tipos que
> muestra la slide 9): CONNACK, PUBACK, PUBREC, PUBREL, PUBCOMP (los cuatro últimos son la
> "conversación" de QoS 1 y 2, ver [QoS](/topics/mqtt/subtopics/qos)), SUBSCRIBE, SUBACK,
> UNSUBSCRIBE, UNSUBACK, PINGREQ, PINGRESP y AUTH.

### Header variable
Parte opcional que depende del tipo de paquete. En un **CONNECT** contiene:

- **Protocol Name**: `"MQTT"`.
- **Protocol Level**: `4` para MQTT 3.1.1.
- **Connect Flags** (ejemplo de la slide): Clean Session = 1, Will Flag = 0, Username = 1,
  Password = 1.
- **Keep Alive**: ejemplo, 60 segundos. Es el período máximo sin tráfico MQTT; si no se
  envía nada en ese lapso el cliente manda **PINGREQ** y el broker responde **PINGRESP**.
  Ayuda a detectar conexiones caídas o inactivas.

### Payload
Es el contenido principal; el header variable sólo lo acompaña. Depende del tipo:

- En **PUBLISH**, el payload es el mensaje de aplicación (p. ej. `"Temperature = 25°C"`).
- En **SUBSCRIBE**, el payload lista los tópicos a los que se suscribe, con sus opciones.

## Método paso a paso
Para leer/armar un paquete MQTT:

1. Lee el byte 1: tipo (4 bits altos), DUP, QoS, RETAIN.
2. Lee el Remaining Length (1 a 4 bytes, largo variable codificado).
3. Si el tipo lo requiere, lee el header variable (para CONNECT: protocol name, level,
   connect flags, keep alive).
4. El resto de bytes, hasta completar Remaining Length, es el payload.

## Errores típicos
- Pensar que el header variable siempre existe: es *opcional*, depende del tipo de paquete.
- Confundir Remaining Length con el largo total del paquete: Remaining Length excluye el
  fixed header.
- Olvidar que DUP, QoS y RETAIN viven en el mismo byte que el tipo de mensaje (son bits,
  no bytes aparte).

| Bits | Valor binario | Valor decimal | Significado |
|---|---|---|---|
| 7-4 (tipo) | `0011` | 3 | **PUBLISH** |
| 3 (DUP) | `0` | 0 | no es una retransmisión |
| 2-1 (QoS) | `10` | 2 | **QoS 2** |
| 0 (RETAIN) | `1` | 1 | el broker debe guardarlo como retenido |

**Respuesta:** $\boxed{\text{PUBLISH, DUP}=0\text{, QoS}=2\text{, RETAIN}=1}$
