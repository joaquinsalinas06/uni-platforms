**1) Transporte y direccionamiento.** DHCP viaja sobre UDP: el cliente usa el puerto 68 y el servidor el 67 *(valores a confirmar en la columna de puertos de tu captura)*. En el Discover el origen es `0.0.0.0` porque el cliente todavía no tiene dirección IP, y el destino `255.255.255.255` (broadcast) porque no conoce al servidor: lo recibe cada host de la LAN y responde el servidor DHCP.

**2) Transaction ID (xid).** Es el mismo en los cuatro mensajes. Sobre UDP, que no tiene conexión ni estado, sirve para que el cliente relacione cada oferta y confirmación con su propia solicitud y descarte las que son para otros clientes.

**3) Parámetros y lease.** En el Offer y el ACK, en la sección de opciones de DHCP, anota la IP ofrecida (*Your (client) IP address*), el *IP Address Lease Time* y al menos dos parámetros más (máscara de subred, router/gateway, servidores DNS). Los valores dependen de tu red.

**4) Capa 2 frente a capa 3.** Aunque el cliente aún no tiene IP, el Offer le llega por la dirección **MAC**: el servidor conoce la MAC del cliente (viene en el Discover) y la usa como destino Ethernet; revisa en la trama del Offer la MAC y la IP de destino que se usaron.

```python
import socket, struct

def build_query(domain, qtype=16):               # 16 = TXT
    header = struct.pack('!HHHHHH', 0x1234, 0x0100, 1, 0, 0, 0)  # id, flags (RD=1), 1 pregunta
    qname = b''.join(bytes([len(p)]) + p.encode() for p in domain.split('.')) + b'\x00'
    return header + qname + struct.pack('!HH', qtype, 1)          # QCLASS = IN

query = build_query('google.com')

udp = socket.socket(socket.AF_INET, socket.SOCK_DGRAM)
udp.settimeout(2)
udp.sendto(query, ('8.8.8.8', 53))
resp, _ = udp.recvfrom(4096)
flags = struct.unpack('!H', resp[2:4])[0]       # segundo campo de 16 bits de la cabecera DNS
tc = (flags >> 9) & 1                           # bit TC
udp.close()

if tc:
    tcp = socket.create_connection(('8.8.8.8', 53), timeout=5)
    tcp.sendall(struct.pack('!H', len(query)) + query)   # DNS sobre TCP: prefijo de 2 bytes
    n = struct.unpack('!H', tcp.recv(2))[0]               # longitud del mensaje de respuesta
    data = b''
    while len(data) < n:
        data += tcp.recv(n - len(data))
    print('TCP payload size:', len(data))
    tcp.close()
```

Puntos del enunciado: usar solo `socket` (sin librerías DNS), aislar el bit TC con operaciones de bits, cambiar a TCP si vale 1, y anteponer / quitar el prefijo de 2 bytes de longitud.

## Pregunta 4. Alternating-Bit Protocol sobre RTP (Python)

ABP da comunicación confiable sobre canales no confiables: dos canales (`chan1`, `chan2`) y dos banderas booleanas; el emisor envía pares `<Bool, Paquete>` y el receptor confirma con el booleano. Solo hay datos del emisor A al receptor B, pero B envía ACK.

```python
rtp_header = struct.pack('!BBHII',
    (version << 6) | (padding << 5) | (extension << 4) | csrc_count,
    payload_type,            # 96
    seq_num,                 # alterna 0 y 1
    int(time.time()),        # timestamp
    ssrc)                    # 1234
return rtp_header + payload.encode()
```

- **Emisor (`rtp_sender`):** socket UDP con `settimeout(2)`; envía a `('127.0.0.1', 5005)`; si llega el ACK con el mismo número de secuencia, lo alterna (`(seq_num + 1) % 2`); si hay `socket.timeout`, reenvía.
- **Receptor (`rtp_receiver`):** `bind(('127.0.0.1', 5005))`, `expected_seq_num = 0`; lee `seq_num` con `struct.unpack('!H', rtp_packet[2:4])`, y el payload en `rtp_packet[12:]`; si coincide, responde `struct.pack('!H', seq_num)` y alterna el esperado; si no, imprime "out-of-order" y sigue.
- **Entregables:** ambos archivos, bitácoras con comunicación exitosa, timeouts y retransmisiones, y la captura del loopback en Wireshark. Experimento opcional: `if random.random() < 0.1: continue` en el emisor y distintos `TIMEOUT`.

> **Diferencia entre enunciados.** El receptor de esta pregunta ignora los duplicados sin reenviar el ACK; la pregunta 3 y las FSM de las slides piden reenviarlo. Con ese receptor, un ACK perdido deja al emisor reintentando sin respuesta.
