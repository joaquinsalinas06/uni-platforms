## 1. Idea y motivación

LAB3 P1 sigue una subida HTTP POST para observar TCP sin confundirlo con HTTP. La captura oficial permite responder con números verificables; la experiencia con tu computadora tendrá otras IP, puertos y tiempos.

## 2. Conceptos

La conversación de `tcp-wireshark-trace1-1.pcapng` es **192.168.86.68:55639 → 128.119.245.12:80**, stream 0. Las tramas 1, 2 y 3 forman el handshake. La trama 4 contiene el inicio del POST, `Seq=1`, y 1448 bytes de carga TCP.

Hay **180 tramas TCP**: 106 segmentos de datos del cliente, uno de datos del servidor y 73 sin carga TCP. Los 153425 bytes de carga del cliente incluyen cabeceras HTTP y contenido de la petición; no deben atribuirse todos al archivo alice.txt. La captura termina sin FIN/RST y no permite describir un cierre observado.

## 3. Método paso a paso

1. Abre la captura; aplica `tcp.stream == 0`.
2. Lee IP, puerto, Seq, Ack, Len y flags. Wireshark muestra secuencias relativas por defecto.
3. Desactiva HTTP en Analyze → Enabled Protocols si quieres ver TCP en Protocol; los paquetes no cambian.
4. Para localizar POST, vuelve a habilitar HTTP y desactiva “Allow Subdissector to reassemble TCP Streams” como indica la guía.
5. Desde el primer POST, empareja cada segmento con el primer ACK posterior que cubra su último byte.
6. Abre Statistics → TCP Stream Graphs → Time Sequence (Stevens); verifica la dirección cliente → servidor.

---

## 4. Ejemplo resuelto

La trama 4 sale en 0.024047 s; la trama 7 reconoce `Ack=1449` en 0.052671 s. Como $1+1448=1449$, confirma el intervalo enviado. $SampleRTT=28.624$ ms. LAB3 fija el primer EstimatedRTT igual a esa muestra; no se incluye el SYN como primer segmento de datos.

## 5. Errores típicos

- Contar todos los paquetes como segmentos de datos.
- Creer que una llamada send equivale a un segmento.
- Identificar slow start con certeza solo por la forma de una captura corta.
