## 1. Idea

Como UDP no repara pérdidas, el ejercicio extra obliga a hacerlo: se simula un canal malo descartando paquetes y se implementa sobre UDP un protocolo de parada y espera (rdt3.0 / alternating-bit).

---

## 2. Conceptos

### Canal con 15 % de pérdidas (Ejercicios Extra, pregunta 3)

Se inyecta en emisor **y** receptor:

```python
import random
# Dentro del bucle de envío/recepción:
if random.random() < 0.15:
    continue  # descarta el paquete a propósito
```

Implementar un rdt3.0 simplificado que entregue un archivo binario (p. ej. una imagen de 2 MB) idéntico entre dos laptops:

- **Emisor:** trozos de 1024 bytes, número de secuencia 0 o 1, espera el ACK específico; con timeout (p. ej. 0,5 s) retransmite el trozo actual.
- **Receptor:** si llega el trozo esperado, lo escribe a disco y envía su ACK; si es un duplicado, descarta los datos pero **reenvía el ACK**.
- **Prueba:** `md5sum` (o `CertUtil -hashfile`) en ambos equipos: deben coincidir pese al 15 % de pérdidas.

### ABP sobre RTP (Ejercicios Extra, pregunta 4)

Emisor (`rtp_sender`, resumido):

```python
sender_socket.settimeout(2)        # timeout de retransmisión
seq_num = 0
while True:
    rtp_packet = create_rtp_packet(seq_num, payload)
    sender_socket.sendto(rtp_packet, receiver_address)   # ('127.0.0.1', 5005)
    try:
        ack_packet, _ = sender_socket.recvfrom(1024)
        ack_seq_num = struct.unpack('!H', ack_packet[:2])[0]
        if ack_seq_num == seq_num:
            seq_num = (seq_num + 1) % 2                  # alterna 0 y 1
    except socket.timeout:
        print(f"Timeout! Resending packet with Seq: {seq_num}")
```

Receptor (`rtp_receiver`): enlaza a `127.0.0.1:5005`, espera `expected_seq_num = 0`; si el número de secuencia coincide, envía el ACK (`struct.pack('!H', seq_num)`) y alterna el esperado; si no, solo imprime "out-of-order" y sigue.

**Observación sobre el código:** este receptor **no reenvía el ACK** de un duplicado, a diferencia de lo que pide la pregunta 3 y de la FSM de rdt2.2/3.0. Si se perdiera un ACK, el emisor retransmitiría y el receptor lo ignoraría. Es una diferencia entre los dos enunciados.

Experimento opcional: añadir `if random.random() < 0.1: continue` en el emisor y variar el `TIMEOUT` para ver el efecto.

Entregables: ambos archivos Python, bitácoras con comunicación exitosa, timeouts y retransmisiones, y la captura del tráfico en el loopback.

## 3. Ejemplo resuelto

Con pérdida del 15 % y trozos de 1024 bytes, un archivo de 2 MB son del orden de $2 \times 1024 \times 1024 / 1024 = 2048$ trozos *(derivado, tomando MB = 1 048 576 bytes)*: cada trozo es un ciclo stop-and-wait; el tiempo total depende de cuántos timeouts de 0,5 s ocurran.

---

## 4. Errores típicos

- Aplicar la pérdida solo en el emisor: el enunciado la pide en ambos lados (pueden perderse los ACK).
- Timeout menor que el RTT real: duplicados innecesarios.
- No reenviar el ACK de un duplicado.
