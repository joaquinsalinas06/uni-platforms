## 1. ¿Qué es una subred en el dibujo?

Imagina varias computadoras conectadas a la misma red local. Pueden comunicarse dentro de esa red sin atravesar un **router**. La clase llama **subred** al conjunto de interfaces que pueden alcanzarse sin cruzar un router intermedio.

Una **interfaz** es la conexión concreta de un equipo a un enlace. Un router que une varias redes tiene varias interfaces; cada una está conectada a su red correspondiente.

La slide 21 usa tres redes **/24**: 223.1.1.0/24, 223.1.2.0/24 y 223.1.3.0/24. El /24 quiere decir que **los primeros 24 de los 32 bits IPv4** indican a qué subred pertenece una dirección. Con ese prefijo, los primeros tres números decimales identifican el bloque.

## 2. Contar subredes: el detalle que suele olvidarse

La diapositiva propone un método visual: imagina que **separas las interfaces de los routers**. Cada conjunto que permanece conectado sin pasar por otro router forma una **isla**; cada isla corresponde a una subred.

En la slide 22, con tres routers, hay **seis subredes**. No son seis porque haya seis computadoras: son tres redes con hosts (**223.1.1.0**, **223.1.2.0** y **223.1.3.0**, todas /24) más tres redes de **enlaces entre routers** (**223.1.7.0**, **223.1.8.0** y **223.1.9.0**, todas /24).

**Regla para un examen:** cuenta las redes donde hay hosts, pero también cada enlace entre routers que constituye su propio segmento de red.

## 3. ¿Por qué querríamos juntar rutas?

Un proveedor de Internet debe informar a otros routers hacia dónde enviar paquetes destinados a sus clientes. Cada información de destino es una **ruta**. Si anuncia un bloque independiente para cada organización, las tablas de rutas pueden volverse grandes.

**Agregación** significa anunciar varios bloques con **un prefijo común**, como decir «todas estas ocho calles pertenecen al mismo distrito». Solo funciona si los bloques son contiguos y su comienzo tiene la alineación correcta en bits.

En el ejemplo de la clase, cada una de ocho organizaciones recibe una subred **/23**. Una /23 conserva 23 bits de red y deja 9 de host: $2^9=512$ direcciones. Ocho bloques tienen **8×512=4096 direcciones**.

Como 4096=$2^{12}$, el prefijo común es 32−12=**/20**. El agregado oficial es **200.23.16.0/20**, que cubre de 200.23.16.0 a 200.23.31.255.

| Subred individual | Tercer octeto cubierto |
|---|---|
| 200.23.16.0/23 | 16–17 |
| 200.23.18.0/23 | 18–19 |
| 200.23.20.0/23 | 20–21 |
| 200.23.22.0/23 | 22–23 |
| 200.23.24.0/23 | 24–25 |
| 200.23.26.0/23 | 26–27 |
| 200.23.28.0/23 | 28–29 |
| 200.23.30.0/23 | 30–31 |

**¿Por qué no sirve cualquier grupo de 4096 direcciones?** Porque un /20 necesita **veinte bits iniciales idénticos**. La cifra total es necesaria, pero también hay que comprobar **contigüidad y alineación**.

## 4. Cuando aparece una ruta más específica

Supón que el cliente con bloque **200.23.18.0/23** cambia de proveedor. El nuevo ISP anuncia específicamente ese /23; el antiguo puede seguir anunciando el grupo general /20.

Un router utiliza la coincidencia de **prefijo más largo**: para un destino como 200.23.18.4 coinciden ambos, pero /23 tiene **más bits fijos**, así que se elige el /23. Para 200.23.24.4 solo se utiliza el /20 agregado si no aparece una excepción más específica.

Eso no significa que una ruta /23 transmita más rápido: simplemente **describe con mayor precisión qué destinos cubre**.

## 5. Comprueba el concepto

Si ves tres LAN y tres enlaces router-router, ¿cuántas subredes hay? **Seis**, siempre que los seis grupos correspondan a redes independientes como en la slide. ¿Cuántos /23 caben dentro de un /20? Hay tres bits adicionales para escoger subredes: **2³ = 8**. ¿Qué ruta se elige entre una /20 y una /23 que ambas coinciden? **La /23**, porque tiene el prefijo coincidente más largo.
