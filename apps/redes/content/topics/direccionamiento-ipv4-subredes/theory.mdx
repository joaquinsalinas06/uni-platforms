## 1. Una IP no es solo un número: te dice dónde buscar

Imagina una universidad con varias redes: una para laboratorios, otra para profesores y otra para estudiantes. Tu laptop necesita enviar datos a un servidor, pero primero debe saber **si el servidor está en su misma red local o necesita atravesar un router**.

Para responder hace falta una dirección **IPv4** y una forma de distinguir qué bits corresponden a la **red** y cuáles al equipo **dentro de esa red**. Esa separación se llama **prefijo de red**.

La presentación explica que una dirección IPv4 identifica una **interfaz**: el punto donde un equipo se conecta a un enlace. Un router tiene varias interfaces porque conecta varias redes. Una laptop puede tener Ethernet y Wi-Fi, también con direcciones distintas.

### ¿Qué es un octeto?

IPv4 tiene **32 bits**. Un bit solo puede valer **0 o 1**. Para que las personas no tengan que leer 32 ceros y unos, escribimos la IP como cuatro números decimales separados por puntos, por ejemplo **223.1.1.1**. Cada uno representa **8 bits**, por eso se llama **octeto**.

La slide 6 muestra:

$$223.1.1.1=11011111.00000001.00000001.00000001_2.$$

No necesitas memorizar esos 32 bits. Lo importante es que **las subredes se calculan comparando bits**, no solo mirando si «se parecen» los números decimales.

## 2. CIDR: decidir cuántos bits son de la red

La clase usa una notación como **200.23.16.0/23**. Esta forma se llama **CIDR**. El **/23** no indica 23 computadoras: indica **23 bits reservados para identificar la red**. Los demás 32 − 23 = **9 bits** quedan para distinguir direcciones dentro del bloque.

Piensa en una dirección postal: «edificio» y «departamento». El prefijo señala el conjunto (red) y la parte host distingue direcciones dentro de ese conjunto. La división no tiene que coincidir con el final de un octeto.

La **máscara** expresa esa división poniendo bits **1** en la parte de red y bits **0** en la parte host. Para /23 la máscara binaria es:

$$11111111.11111111.11111110.00000000.$$

Ahora convierte cada octeto a decimal: **255.255.254.0**. Fíjate en el tercero: 11111110 equivale a 254, no a 255. Ese único cero permite que un /23 abarque **dos valores consecutivos del tercer octeto**.

## 3. Hallar la dirección de red: ¿dónde empieza el bloque?

Una dirección de equipo puede tener varios bits host encendidos. Para saber **qué subred representa**, aplicamos un **AND bit a bit** entre IP y máscara: solo queda un 1 donde **ambos bits** son 1. Los bits host se vuelven cero y obtenemos **la primera dirección del bloque**, llamada **dirección de red**.

Tomemos el caso de la clase **200.23.16.0/23**. La máscara es 255.255.254.0. El tercer octeto de la IP es 16, que en binario es 00010000; al hacer AND con 11111110 se mantiene 00010000. El cuarto octeto se vuelve cero. Por tanto, **la red es 200.23.16.0/23**.

¿Y si la IP fuera **200.23.19.140/23**? El tercer octeto 19 es 00010011. Al hacer AND con 11111110, su último bit pasa a cero y queda **18**. El cuarto octeto también se hace cero. Por eso la red correspondiente es **200.23.18.0/23**. No te quedes con el 19 simplemente porque aparece en la IP del equipo.

## 4. Broadcast: ¿dónde termina el bloque?

En una subred IPv4 ordinaria, la primera dirección identifica la red y la última es la dirección de **broadcast de subred**. Para encontrar esa última, deja igual el prefijo y pon **todos los bits host a 1**.

Si la red era 200.23.16.0/23, hay nueve bits host. Al ponerlos a uno, el tercer octeto pasa de 16 a **17** y el último vale **255**. El broadcast es **200.23.17.255**.

| Resultado para 200.23.16.0/23 | Valor | De dónde salió |
|---|---|---|
| Máscara | 255.255.254.0 | 23 bits de red a 1 |
| Dirección de red | 200.23.16.0 | IP AND máscara |
| Broadcast | 200.23.17.255 | Todos los bits host a 1 |
| Direcciones totales | **512** | 2 elevado a 9 bits host |
| Hosts utilizables en esta subred ordinaria | **510** | 512 menos red y broadcast |
| Rango habitual de hosts | 200.23.16.1 a 200.23.17.254 | Entre los dos extremos |

La slide 15 incluye también **127.0.0.1**, llamada dirección de **loopback**, para hablar con el propio equipo; y **255.255.255.255**, broadcast limitado. No confundas este último con el broadcast calculado de una subred como /23.

## 6. ¿Por qué los proveedores agrupan direcciones?

Supón que un proveedor conecta ocho organizaciones, cada una con un bloque de 512 direcciones. En lugar de anunciar ocho rutas independientes a toda la red, puede **agregarlas en una ruta más general** si los bloques son contiguos, tienen el prefijo común adecuado y están alineados.

Las slides muestran los ocho bloques /23:

| Bloque | Terceros octetos cubiertos |
|---|---|
| 200.23.16.0/23 | 16 y 17 |
| 200.23.18.0/23 | 18 y 19 |
| 200.23.20.0/23 | 20 y 21 |
| 200.23.22.0/23 | 22 y 23 |
| 200.23.24.0/23 | 24 y 25 |
| 200.23.26.0/23 | 26 y 27 |
| 200.23.28.0/23 | 28 y 29 |
| 200.23.30.0/23 | 30 y 31 |

Son 8×512 = **4096 direcciones**. Como 4096=2^12, el prefijo común tiene **32−12 = 20 bits**: todo el conjunto puede anunciarse como **200.23.16.0/20**.

Si una organización cambia de proveedor y el nuevo anuncia **200.23.18.0/23**, esa ruta es **más específica** que /20. Para las direcciones de ese /23 el router elige el anuncio más específico que coincida. El resto de organizaciones siguen cubiertas por el /20.

## 7. DHCP: ¿cómo consigue mi laptop una IP al conectarse?

Al entrar a una Wi-Fi, normalmente no eliges a mano todos los números. El protocolo **DHCP** permite que un servidor conceda una dirección **temporal** y otros parámetros, como máscara, primer router y DNS.

El intercambio de la slide 28 se recuerda con **DORA**:

1. **Discover:** el cliente, que todavía no tiene la IP concedida, busca un servidor mediante un mensaje UDP enviado por broadcast.
2. **Offer:** el servidor propone una dirección, por ejemplo **223.1.2.4** en la figura oficial, y un tiempo de concesión de 3600 segundos.
3. **Request:** el cliente solicita usar esa dirección propuesta.
4. **ACK:** el servidor confirma que el cliente puede configurarla.

El ACK de DHCP **no es un ACK de TCP**: DHCP utiliza **UDP**, con puertos 68 para el cliente y 67 para el servidor, tal como muestra la presentación.

## 8. IP y MAC no responden a la misma pregunta

Una dirección **IP** identifica la interfaz de red para alcanzar un destino a través de subredes. Una dirección **MAC**, normalmente de 48 bits en la LAN que estudian las slides, sirve para entregar una **trama por el enlace local**. Un datagrama puede conservar su destino IP mientras cada enlace utiliza sus propias direcciones de entrega.

Las herramientas de la presentación muestran distintas partes del problema: **ifconfig** permite inspeccionar interfaces, **netstat -nr** la tabla de rutas y **traceroute** los saltos visibles hacia un destino. Ninguna sustituye por sí sola el cálculo de la máscara.

## 9. Qué deberías poder explicar sin memorizar

¿Por qué /23 contiene 512 direcciones? Porque 32−23=9 bits quedan para host y 2^9=512. ¿Por qué el broadcast es 200.23.17.255? Porque esos nueve bits host se pusieron a uno. ¿Por qué la figura de tres routers incluye seis subredes? Porque los enlaces entre routers también cuentan. ¿Por qué DHCP usa 0.0.0.0 al principio? Porque el cliente todavía no tiene confirmada su dirección.
