## 1. Idea

Cuando el DNS local no tiene el nombre en caché, tiene que recorrer la jerarquía. Hay dos estilos de consulta:

| | **Iterativa** | **Recursiva** |
|---|---|---|
| El servidor contactado | Responde con el nombre del siguiente servidor: "no conozco este nombre, pregunta a este" | Se encarga de resolver el nombre por el cliente |
| Quién recorre la cadena | El DNS local (pregunta a todos) | Cada servidor consulta al siguiente |
| Carga en los niveles altos | Baja | Alta (pregunta de las slides: ¿carga pesada en los niveles altos?) |

**En la práctica**: la consulta del host al DNS local es **recursiva**, y las consultas restantes del DNS local a raíz, TLD y autoritativo son **iterativas**.

## 3. Retardos (Ex 3, pregunta 3)

Sea $\text{RTT}_0$ el retardo cliente-DNS local y $\text{RTT}_1$, $\text{RTT}_2$, $\text{RTT}_3$ los de raíz, TLD y autoritativo.

- **Iterativa**, desde el DNS local: cada consulta es un viaje de ida y vuelta separado.

$$T = \text{RTT}_0 + \text{RTT}_1 + \text{RTT}_2 + \text{RTT}_3$$

- **Recursiva pura**: la consulta y la respuesta recorren la cadena raíz, TLD, autoritativo y vuelven por el mismo camino; se suma el RTT de cada tramo de la cadena. Si $\text{RTT}_2$ y $\text{RTT}_3$ se entienden como los RTT de los tramos entre servidores, la fórmula es la misma.
- **Caché en el DNS local**: evita consultar raíz y TLD, así que baja el tráfico hacia los niveles altos. El costo es que puede devolver datos **desactualizados** hasta que expire el TTL: se gana rapidez y se pierde algo de consistencia.

---

## 4. Errores típicos

- Decir que en la iterativa los servidores "se pasan" la consulta: es el DNS local quien va preguntando.
- Invertir el estilo de cada tramo: host a DNS local es recursivo; DNS local a la jerarquía es iterativo.
- Olvidar que el DNS local responde de caché cuando puede.
