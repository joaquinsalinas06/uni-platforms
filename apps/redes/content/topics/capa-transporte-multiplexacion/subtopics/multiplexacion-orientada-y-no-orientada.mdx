## 1. Idea

Dos reglas distintas para elegir el socket receptor: UDP usa solo el puerto destino; TCP usa los cuatro valores (4-tupla).

---

## 2. Conceptos

### Sin conexión (UDP)

- Al crear el socket hay que indicar un puerto local: `DatagramSocket mySocket1 = new DatagramSocket(12534)`.
- Al crear un datagrama para enviar, se indica **IP destino** y **puerto destino**.
- Al recibir, el host mira el puerto destino y entrega al socket con ese puerto. Datagramas con el mismo puerto destino pero distinta IP u otro puerto origen van al **mismo** socket.

### Orientada a conexión (TCP)

- Un socket TCP se identifica por la **4-tupla**: IP origen, puerto origen, IP destino, puerto destino.
- El receptor usa los **cuatro** valores para dirigir el segmento al socket.
- Un servidor puede tener muchos sockets TCP a la vez, cada uno con su 4-tupla y asociado a un cliente distinto.

## 3. Ejemplo resuelto

Ejercicios 3, pregunta 5: servidor web B (puerto 80), host A (puerto origen 26145) y host C con dos conexiones (puertos origen 7532 y 26145). Segmentos **del servidor hacia los clientes** (se invierten los valores del cliente):

| Hacia | Puerto origen | Puerto destino | IP origen | IP destino |
|---|---|---|---|---|
| Host A | 80 | 26145 | B | A |
| Host C (proceso izquierdo) | 80 | 7532 | B | C |
| Host C (proceso derecho) | 80 | 26145 | B | C |

Aunque A y C usen el puerto 26145, el servidor distingue las conexiones por la IP.

---

## 4. Errores típicos

- Concluir que dos conexiones con el mismo puerto origen colisionan: la 4-tupla incluye la IP.
- Confundir "servidor con un socket de escucha" con un socket por cliente: en TCP hay uno por conexión.
