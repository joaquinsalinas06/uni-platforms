## 1. Idea

Los dos mecanismos agregan a **cada segmento TCP** de la sesión BGP un código calculado con una **clave compartida** por los dos pares. Quien no tiene la clave no puede fabricar un código válido.

## 2. Comparación (slide 26)

| | TCP MD5 | TCP-AO |
|---|---|---|
| Base | secreto compartido + **digest MD5 con clave** | algoritmos **MAC modernos** |
| Qué verifica | autenticidad de cada segmento TCP | autenticidad de cada segmento TCP |
| Claves | mecanismo **heredado**, poca agilidad para cambiar claves | **mejor rotación** de claves (key rollover) |
| Replay | — | **mejor protección contra replay** |
| Estado | legado | diseñado para **reemplazar** a TCP MD5 |
| ¿Cifra BGP? | **no** | **no** |

---

## 3. Errores típicos

- Decir que TCP MD5 "cifra con MD5": calcula un digest con clave, no cifra.
- Elegir TCP MD5 por ser "más simple" cuando la pregunta es sobre replay o rotación: ahí gana TCP-AO.
