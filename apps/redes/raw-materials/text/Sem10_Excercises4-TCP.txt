  Objective. Capture and analyze a real TCP connection established between your computer and a
web server. Use Wireshark and a web browser to observe connection establishment, data transfer, and
connection termination.
  Instructions.
   1) Open Wireshark and select your active network interface.
   2) Apply a capture or display filter for HTTP/HTTPS TCP traffic (e.g., tcp.port == 80 or tcp.port
      == 443).
   3) Visit a lightweight webpage such as http://example.com or http://httpbin.org/get.
   4) Stop the capture once the page has fully loaded.
   5) Isolate the TCP stream corresponding to the connection between your host and the server.
  Questions.
   1) What were the IP addresses and port numbers used by the client and the server?
   2) Which specific packet numbers correspond to the Three-Way Handshake? Include a screenshot.
   3) What header fields and flags confirm that the TCP connection was successfully established?
   4) How many data-carrying TCP segments were transmitted before the connection closed?
   5) Which packets indicate the connection termination sequence (FIN and ACK)?

Question 7. Local TCP Client–Server Communication in Python:
  Objective. Design and analyze a custom TCP communication system using Python sockets to inspect
how application-level delays and sequential transmissions interact with TCP mechanisms.
  Instructions.
   1) Implement a TCP server in Python capable of handling multiple consecutive client messages within
      a persistent connection.
   2) Upon receiving a message from the client, the server must wait for 2 seconds (simulating process-
      ing/network delay) before sending back an application-layer acknowledgment string.
   3) Implement a TCP client that:
        a. Establishes a connection with the server,
        b. Sends 3 separate text messages (waiting 1 second after receiving each reply before sending the
           next),
        c. Waits for the server’s reply after each message,
        d. Measures and displays the elapsed application-level Round Trip Time (RTT) for each message.
   4) Run the experiment first on the loopback interface (127.0.0.1), and then—if possible—between
      two machines on the same local network.
   5) Capture the packet exchange in Wireshark using the display filter:
                                      tcp.port == <chosen port>
  Questions.
   1) How many TCP segments were exchanged per application message (distinguish between transport-
      layer TCP ACKs and application-layer replies)?
   2) How do the Sequence (Seq) and Acknowledgment (Ack) numbers evolve across the 3 sequential
      messages?
   3) Why does Wireshark send a transport-layer TCP ACK almost immediately, even though the Python
      server waits 2 seconds before sending its reply?
   4) Compare the application-layer RTT measured by your Python client with the TCP RTT reported
      by Wireshark (tcp.analysis.ack rtt). Why do they differ?
   5) Observe the TCP window size throughout the communication. Does it change between messages,
      and what does it represent?
   6) What happens at the packet level (RST or FIN) if you abruptly terminate the server process (Ctrl+C)
      while the client is still connected? How does TCP handle this compared to UDP?
   7) List the exact chronological sequence of TCP flags (SYN, ACK, PSH, FIN) observed from start to finish
      and explain the role of the PSH flag.
