## Motivación

Tenemos un arreglo $D[0..n-1]$ y queremos el índice del mínimo en $D[i..j]$. La sparse table responde en $O(1)$, pero cuesta $O(n\lg n)$ de memoria. Con $n=10^6$ son unos $2\cdot10^7$ entradas. Queremos lo mismo con $O(n)$ de preprocesamiento.

El truco es que el arreglo que aparece en el árbol de Euler no es arbitrario. Dos posiciones consecutivas difieren en exactamente $+1$ o $-1$. Esa regularidad permite compartir trabajo entre bloques distintos.

## Intuición dibujada

Partimos $D$ en bloques de tamaño $b\approx\tfrac12\lg n$. Cada bloque tiene dos caras:

- Su **mínimo** y la posición de ese mínimo: un número por bloque. Son sólo $n/b=O(n/\lg n)$ números, así que una sparse table sobre ellos cabe en $O(n)$.
- Su **patrón**: la secuencia de pasos $+1$ o $-1$ entre entradas consecutivas. Dos bloques con el mismo patrón tienen las mismas respuestas locales, aunque sus valores estén desplazados.

## Definición y notación

| Símbolo | Qué mide | Qué pasa si crece |
| --- | --- | --- |
| $n$ | longitud de $D$ | sube el costo total |
| $b = \max(1,\lfloor \lg n/2\rfloor)$ | tamaño de bloque | más bloques, pero patrones más largos |
| $n_b = \lceil n/b\rceil$ | número de bloques | la sparse table macro tiene $n_b\lg n_b$ entradas |
| $\mathrm{pat}[t]$ | patrón de pasos del bloque $t$, $b-1$ bits | define qué tabla micro usar |
| $T[p][l][r]$ | posición local del mínimo de $D[l..r]$ para el patrón $p$ | una tabla por patrón; $b(b+1)/2$ celdas útiles |
| $\mathrm{bmin}[t]$, $\mathrm{bidx}[t]$ | mínimo del bloque $t$ y su posición global | alimentan la sparse table macro |

Los pasos de un bloque son $\delta_k = D[k+1]-D[k]\in\{+1,-1\}$ para $k$ dentro del bloque. El patrón es esa secuencia codificada en $b-1$ bits. Como el arreglo de Euler sube o baja en cada paso, todo $D$ cumple esto.

## Por qué sólo importa el patrón

Si dos bloques tienen los mismos pasos, la diferencia entre sus valores es constante. Restar la base a cada bloque lo deja igual. Así, el índice del mínimo de un rango dentro del bloque sólo depende del patrón.

El argumento tiene un matiz importante. La tabla micro dice **qué posición** gana dentro del bloque, pero no compara con otros bloques. Para comparar hay que volver a las alturas originales, porque cada bloque tiene su propia base. Por eso la respuesta final se elige con los valores reales.

## Preprocesamiento

Algoritmo (en prosa):

1. Fijar $b=\max(1,\lfloor\lg n/2\rfloor)$ y $n_b=\lceil n/b\rceil$.
2. Para cada bloque $t$: guardar su mínimo y posición en $\mathrm{bmin}[t]$, $\mathrm{bidx}[t]$, y calcular $\mathrm{pat}[t]$ leyendo los $b-1$ pasos.
3. Construir la sparse table sobre $\mathrm{bmin}[0..n_b-1]$.
4. Para cada patrón $p$ que aparece, llenar $T[p][l][r]$ para todo $0\le l\le r<b$, recorriendo $r$ y manteniendo el mínimo.

El paso 2 recorre cada elemento una vez. El paso 4 sólo llena tablas de patrones que aparecen, nunca más de $2^{b-1}$.

## Consulta

Para $\mathrm{RMQ}(i,j)$ con $s=\lfloor i/b\rfloor$, $t=\lfloor j/b\rfloor$:

1. Si $s=t$: la respuesta está dentro de un bloque. Se devuelve $s\cdot b+T[\mathrm{pat}[s]][i\bmod b][j\bmod b]$.
2. Si $s<t$: calcular el **sufijo** del bloque $s$ desde $i$, con $a=s\cdot b+T[\mathrm{pat}[s]][i\bmod b][b-1]$.
3. Calcular el **prefijo** del bloque $t$ hasta $j$, con $c=t\cdot b+T[\mathrm{pat}[t]][0][j\bmod b]$.
4. Si hay bloques enteros entre $s$ y $t$: consultar la sparse table en $[s+1,\,t-1]$ y obtener $u=\mathrm{bidx}[\cdot]$.
5. Devolver el candidato de menor **valor** entre $a$, $c$ y, si existe, $u$.

Se hacen como mucho dos consultas micro, una consulta macro y tres comparaciones. Todo es $O(1)$.

## De dónde sale la cota

La parte macro tiene $n_b=\lceil n/b\rceil$ entradas, y como $b\approx\tfrac12\lg n$, $n_b\approx 2n/\lg n$. La sparse table sobre $n_b$ valores tiene $n_b\lceil\lg n_b\rceil$ entradas:

$$n_b\lg n_b \le \frac{2n}{\lg n}\cdot \lg n = 2n = O(n)$$

Los patrones: cada bloque tiene $b-1$ pasos, así que hay $2^{b-1}$ patrones. Como $b\le\tfrac12\lg n$,

$$2^{b-1}\le 2^{\frac12\lg n}=\sqrt n$$

Cada patrón tiene $b(b+1)/2\le b^2$ celdas. El total micro es

$$\sqrt n\cdot b^2 \le \sqrt n\cdot\tfrac14\lg^2 n = O(\sqrt n\,\lg^2 n)=o(n)$$

Esto da el preprocesamiento total:

$$O(n)\;(\text{bloques y patrones}) + O(n)\;(\text{macro}) + o(n)\;(\text{micro}) = O(n)$$

Y la consulta es $O(1)$: dos celdas micro, dos celdas macro y tres comparaciones.

## Errores típicos y casos límite

- **Bloque último más corto.** Si $n$ no es múltiplo de $b$, el último bloque tiene menos de $b$ entradas. Su patrón tiene menos bits, y la tabla debe usar el tamaño real o rellenar con un patrón válido. No debes leer posiciones fuera de $D$.
- **Comparar alturas normalizadas.** Restar la base hace que dos bloques distintos sean comparables sólo dentro de la tabla micro. Entre bloques, el candidato se compara con su valor original.
- **Consulta dentro de un bloque.** Si $s=t$, no hay sufijo ni prefijo: sólo una celda micro. Usar la fórmula de dos bordes ahí da respuestas incorrectas.
- **Bloques adyacentes.** Si $t=s+1$, no hay bloques intermedios. La parte macro se omite.
- **Ventana macro vacía.** La parte macro sólo se consulta si $t-s>1$.
- **Empates.** Si dos candidatos tienen el mismo valor, la convención del RMQ decide qué índice se devuelve. Hay que fijarla antes de llenar las tablas.

## Conexión

- Parte del problema de [RMQ estático](/structures/static-rmq): la sparse table es la versión $O(n\lg n)$ de la parte macro.
- Se usa con [LCA por tour de Euler](/structures/lca-euler-tour): el árbol de Euler produce un arreglo ±1, y la consulta de LCA se reduce a RMQ sobre él.
