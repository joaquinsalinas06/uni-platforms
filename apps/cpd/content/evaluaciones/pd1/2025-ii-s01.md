## Pregunta 1 — Búsqueda (2 pts)

Un problema de optimización y búsqueda puede representarse con un árbol como el mostrado en la figura.

Gráfica: árbol de búsqueda con profundidad $D$ y grado (máximo) $G$ por nodo, donde se resalta un subárbol $G$ (un hijo) y su profundidad restante $D$ hasta las hojas.

Si se utiliza el método de primero en profundidad, la cantidad de tareas de búsqueda depende de la profundidad $D$ y el grado (máximo) de cada nodo, tal que: # tareas (de búsqueda) $= \prod_{i=1}^{D} G$, o bien $G^D$.

Aplique una **descomposición funcional** (de tareas), para optimizar el algoritmo en paralelo que realice la búsqueda en este árbol, utilizando el **método de Foster**. Siga los pasos: **particionamiento** (defina adecuadamente la tarea primitiva), **comunicación** (cantidad de canales entre tareas creadas), **aglomeración** (cantidad de sub-árboles de búsqueda que pueden ser realizadas por un solo proceso), y **mapping** (cantidad de procesos necesarios). (0.5 pts/paso)

Note que un sub-árbol puede ser también una tarea. Como se observa, una tarea puede generar más tareas.

Considere que el problema original tiene como parámetros $G=10$, $D=12$, y cada proceso puede crear como máximo $10^9$ tareas, debido a limitaciones de memoria.

### Solución

**Método de Foster:**

- **Particionamiento:** se puede iniciar definiendo una tarea de búsqueda por cada celda de la malla (cada nodo del árbol). En total tendremos $G^D = 10^{12}$ tareas, cada una de complejidad $O(1)$.
- **Comunicación:** cada tarea, de no encontrar la solución, necesita generar (comunicarse) las siguientes tareas. Si asumimos una distribución de árbol como en la figura, un aproximado de $10^{12}$ canales de comunicación.
- **Aglomeración:** para reducir canales de comunicación, se aglomeran tareas, cada una de las cuales obtiene un conjunto de celdas, por ejemplo los 3 primeros hijos de búsqueda pueden aglomerar a todos sus descendientes. De esta manera son 3 canales de comunicación.
- **Mapping:** dado que cada proceso puede generar sólo hasta $10^9$ tareas, la solución anterior no es factible, ya que cada uno tendría que generar aproximadamente $10^{12}$ tareas. Por ello, se asignan $10^9$ tareas por proceso, lo que deriva en $10^3$ canales de comunicación.

## Pregunta 2 — Escalabilidad (1 pt)

El algoritmo de ordenamiento por ranking (que veremos en clase) tiene una complejidad

$$T_{p,n} = O\left(\sqrt{p}\,n + \frac{n}{\sqrt{p}} + \frac{n\log n}{p}\right)$$

donde $n$ es el tamaño del problema y $p$ la cantidad de procesos.

#### (a) Determine el speedup y eficiencia del algoritmo ¿Cómo depende el número de procesos $p$ de la cantidad de elementos $n$, si el speedup tiene una complejidad ideal ($S=O(p)$)? (0.3 pts)

#### (b) Con 16 procesos, se ordena un array de $2^{10}$ elementos a una alta eficiencia. Se quiere ordenar $2^{20}$ elementos ¿Cuántos procesos se necesitan para mantener la eficiencia constante? **Nota:** derive una expresión para la eficiencia y encuentre la condición para $E=O(1)$ (0.5 pts)

#### (c) Bajo esa condición ¿Qué tipo de escalabilidad muestra el algoritmo de ordenamiento por ranking? (0.2 pts)

### Solución

#### (a)

El tiempo total paralelo es

$$T_{comp} + T_{comm} = O\left(\sqrt{p}\,n + \frac{n}{\sqrt{p}} + \frac{n\log n}{p}\right)$$

Ya que $T_s = O(n\log n)$,

$$S = O\left(\frac{n\log n}{\sqrt{p}\,n + \frac{n}{\sqrt{p}} + \frac{n\log n}{p}}\right)$$

$S=O(p)$ equivale a la condición $E=O(1)$. Con

$$E = O\left(\frac{1}{1+\sqrt{p}\,n + \frac{n}{\sqrt{p}}}\right) = O\left(\frac{1}{1+\frac{p^{3/2}}{\log n}}\right)$$

se obtiene $\log n \propto p^{3/2}$.

#### (b)

La condición de escalabilidad permite definir la relación

$$\frac{\log n_1}{\log n_2} = \frac{p_1^{3/2}}{p_2^{3/2}}$$

Reemplazando los datos, $n_1 = 2^{10}$, $p_1 = 16$, $n_2 = 2^{20}$, se obtiene $p_2 \approx 26$.

#### (c)

Ya que $n$ y $p$ crecen, y $E=O(1)$, muestra escalabilidad débil.

## Pregunta 3 — DAG (2 pts)

Dado el siguiente código:

```c
double function() {
  int i, n, j;
  double *v, *w, *x, *y, *z, sw, res;
  scan(&n, &v, &w, &x, &y, &z); /* Leer los vectores v, w, x, y, de dimension n*/

  modifica_v(n,y);              // Tarea 1, O(n log(n))
  modifica_w(n,w);              // Tarea 2, O(n^2/log(n))
  modifica_z(n,z);               // Tarea 3, O(n^2)
  /* Tarea 4*/
  for (j=0; j<n; j++){
    sv=0;
    for (i=0; i<n; i++) sv=sv+v[i]*w[i];
    for (i=0; i<n; i++) v[i]=sv+v[i]; }
  /* Tarea 5*/
  for (j=0; j<n; j++){
    sw=0;
    for (i=0; i<n; i++) sw=sw+w[i]*z[i];
    for (i=0; i<n; i++) z[i]=sw*z[i]; }
  /* Tarea 6*/
  sx=0;
  for (j=0; j<n; j++) y[j]=sx*z[j];
  /* Tarea 7*/
  x=sv*sw;
  for (i=0; i<n; i++) res = res+x*z[i]+x*y[i];
  return res;
}
```

#### (a) Diagrame el DAG correspondiente al código (no paralelice internamente las tareas) (0.4 pts)

#### (b) Determine $T_s$, $T_\infty(n)$, $W(n)$, $S(n)$. Considere que $T_p = T_{comp} + T_{comm}$, donde $T_{comm} = O(\beta\cdot x)$, siendo $x$ la data que es copiada de función a función. E.g. $T_1$ envía el vector $v$, de tamaño $n$, a $T_4$, por lo que $T^{1,4}_{comm} = O(\beta\cdot n)$. El factor $\beta$ representa el ancho de banda o velocidad de envío por Byte. No simplifique términos de complejidad (0.8 pts)

#### (c) Optimice el paralelismo según Foster (aglomeración) y vuelva a calcular $T_s$, $T_\infty(n)$, $W(n)$, $S(n)$ (0.8 pts)

### Solución

#### (a) DAG del código

Nodos: $T_1$ ($O(n\log n)$), $T_2$ ($O(n^2/\log n)$), $T_3$ ($O(\log n)$), con aristas $T_1 \xrightarrow{v} T_4$, $T_2 \xrightarrow{w} T_4$, $T_2 \xrightarrow{w} T_5$, $T_3 \xrightarrow{z} T_5$; $T_4$ ($O(n^2)$) y $T_5$ ($O(n^2)$) alimentan a $T_6$ ($O(n)$, aristas $sv$, $sw$) y $T_6 \xrightarrow{y} T_7$ ($O(n)$).

#### (b) Métricas (sin optimizar)

$$T_s(n) = O(n^2 + n + n\log n + n^2/\log n)$$

$$T_\infty(n) = O(n\log n + n^2 + n)$$

$$T_{comm} = O(n\beta) \quad\text{(se ignora envío de elementos simples)}$$

$$T_p = O(n^2 + n + n\log n + n\beta)$$

$$S(n) = O\left(\frac{n^2+n+n\log n+n^2/\log n}{n\log n+n^2+n+n\beta}\right)$$

#### (c) Optimización (aglomeración)

Si aglomeramos tareas para reducir canales de comunicación:

$$T_s(n) = O(n^2 + n + n\log n + n^2/\log n)$$

$$T_\infty(n) = O(n\log n + n^2 + n)$$

$$T_{comm} = O(n\beta) \quad\text{(se ignora envío de elementos simples)}$$

$$T_p = O(n^2 + n + n\log n + n\beta)$$

$$S(n) = O\left(\frac{n^2+n+n\log n+n^2/\log n}{n^2/\log n+n^2+n+n\beta}\right)$$

Es decir, el tiempo asintótico no cambia, pero la cantidad de canales de comunicación total sí (se reduce al aglomerar las tareas $T_4$/$T_5$ en un mismo proceso).
