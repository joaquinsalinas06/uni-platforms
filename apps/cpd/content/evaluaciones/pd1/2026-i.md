## Pregunta 1 — N-Cuerpos (2.5 pts)

El problema de N-Cuerpos consiste en el cálculo de la fuerza gravitatoria que actúa en cada partícula con respecto al resto de partículas.

Gráfica: nube de partículas de distinta masa $m_i$, cada una atrayendo gravitatoriamente a una partícula central $m$, con flechas representando la fuerza de cada partícula sobre las demás.

El cálculo de la fuerza entre dos partículas se realiza aplicando $F = \dfrac{G\cdot m_1\cdot m_2}{r^2}$.

Aplique una **descomposición de dominio** (datos), para optimizar el algoritmo de N-Cuerpos en paralelo, utilizando el **método de Foster**:

- **particionamiento** (tarea primitiva) (0.5 pts)
- **comunicación** (cantidad de canales entre tareas creadas) (0.5 pts)
- **aglomeración** (cantidad de partículas que pueden ser calculadas por tarea) (0.5 pts)
- **mapping** (cantidad de procesos necesarios) (0.5 pts)

Con la condición de que cada proceso tiene una velocidad de 2.5 GHz y puede albergar en memoria un máximo de $10^9$ partículas. ¿Cuál sería el tiempo de ejecución en paralelo de un modelo de N-Cuerpos con $N=10^{12}$ partículas (no considere tiempo de comunicación)? (0.5 pts)

**Nota:** la velocidad por proceso en FLOPs se puede obtener asumiendo 1 ciclo por operación de coma flotante.

### Solución

**Método de Foster:**

- **Particionamiento:** se puede iniciar definiendo una tarea de cálculo de la fuerza entre dos cuerpos, es decir $\dfrac{n(n-1)}{2} \approx 10^{24}$ tareas (evitando duplicados). La tarea de realizar la suma acumulada de las fuerzas parciales por partícula duplica esta cantidad, pero el orden de magnitud se mantiene.
- **Comunicación:** cada tarea necesita comunicarse, enviar el cálculo a todas las demás tareas. Se puede construir un grafo completo, con $\dfrac{n(n-1)}{2} \approx 10^{24}$ aristas (canales de comunicación).
- **Aglomeración:** para reducir canales de comunicación, se permite que cada tarea haga el cálculo de $10^5$ partículas. Se construye un grafo completo con $10^7$ vértices, y $10^{14}$ canales de comunicación.
- **Mapping:** dado que cada proceso puede almacenar como máximo $10^9$ cuerpos, se deriva en un grafo completo de $10^3$ canales de comunicación.

**Tiempo en paralelo:** cada proceso almacena $10^9$ cuerpos. 2.5 GHz equivalen a 2.5 GFLOPs. La cantidad total de operaciones según la fórmula dada es $4\cdot 10^{24} + 10^{12}$ (cálculo de fuerzas + suma acumulada de fuerzas externas), por lo que el tiempo en paralelo es (se ignora el segundo término)

$$\frac{4\cdot 10^{24}}{2.5\cdot 10^{9}} = 1.6\cdot 10^{12} \text{ segundos} \approx 51000 \text{ años}$$

## Pregunta 2 — DAG (2 pts)

El DAG muestra tareas y su respectiva complejidad local:

Grafo: $T_1$ ($\log n$) $\to T_2$ ($\log n$), $T_3$ ($n^2$); $T_2 \to T_5$ ($n$), $T_4$ ($2n^3$); $T_3 \to T_4$, $T_6$ ($5n^3$); $T_4, T_5 \to T_7$ ($\log n$); $T_6 \to T_9$; $T_7 \to T_8$ ($n^2$); $T_8, T_9 \to T_9 \to T_{10}$ ($n^2$), con $T_{10}$ recibiendo también de $T_8$; salida final en $T_{10}$ con complejidad local $\log n$.

#### (a) Encuentre $T_s$, $T_\infty$ y $W$ (0.5 pts)

#### (b) Determine una expresión para el Speedup (recuerde no simplificar términos) (0.5 pts)

#### (c) Aplique aglomeración y genere otro DAG, tal que pueda incrementar el Speedup. Encuentre el factor de mejora respecto al primer DAG. Asuma que en algoritmos secuenciales (locales) se pueden simplificar términos de complejidad. Comente el resultado (1 pt)

### Solución

#### (a)

$$T_s = O(\log n + n + n^2 + n^3) \equiv W$$

$$T_p = O(\log n + n + n^2 + n^3)$$

#### (b)

$$S = O\left(\frac{\log n+n+n^2+n^3}{\log n+n+n^2+n^3}\right) = O(1)$$

#### (c)

Aplicando aglomeración se genera un DAG optimizado, con

$$T_s = O(\log n+n+n^2+n^3) \equiv W$$

$$T_p = O(\log n+n^3)$$

$$S = O\left(\frac{\log n+n+n^2+n^3}{\log n+n^3}\right) = O\left(1+\frac{n+n^2}{\log n+n+n^3}\right) \approx O\left(1+\frac{1}{n}\right)$$

un speedup mayor a 1 pero en una fracción que es más pequeña mientras crece $n$. Por lo que no se considera una mejora considerable en velocidad al paralelizar.

## Pregunta 3 — Cajeros (1.5 pts)

Un banco tiene 4 cajeros (procesadores) con la siguiente configuración:

$C_1$: `x=leer_cuenta(v); x+=cantidad; escribir_cuenta(x,v)` — $C_2$: `y=leer_cuenta(v); y+=cantidad; escribir_cuenta(y,v)` — memoria local compartida entre $C_1$ y $C_2$.

$C_3$: `z=leer_cuenta(v); z+=cantidad; escribir_cuenta(z,v)` — $C_4$: `w=leer_cuenta(v); w+=cantidad; escribir_cuenta(w,v)` — memoria local compartida entre $C_3$ y $C_4$.

Ambos pares de cajeros se comunican entre sí a través de una **red de comunicación**.

Los cajeros $C_1$ y $C_2$ están instalados en un mismo proceso (espacio compartido de memoria), así como los cajeros $C_3$ y $C_4$. Pero entre ellos sólo es posible intercambiar información a través de una red. Cada cajero puede depositar o retirar cualquier cantidad en o desde la cuenta.

- Desarrolle un algoritmo (pseudocódigo) que permita actualizar una cuenta ($v$), luego del uso de los cajeros, en cualquier orden y con cualquier frecuencia (0.5 pts)
- Comente si hay forma de paralelizar este algoritmo (0.5 pts)
- ¿Puede clasificar este problema según la taxonomía de Flynn? (0.5 pts)

**Nota:** los cajeros que comparten memoria pueden leer y escribir (read/write) en memoria directamente. Los cajeros que no comparten memoria deben enviar/recibir la información entre ellos. Utilice instrucciones de envío/recibo para realizar ello. E.g. `send(v, C1)` significa que se envía el valor de $v$ al cajero 1.

Se considera que $C_1$ y $C_2$ forman un nodo, $C_1$ es maestro en ese nodo (el que comunica). $C_3$ y $C_4$ forman el segundo nodo, $C_3$ es maestro en ese nodo.

### Solución

#### Pseudocódigo (nodo $C_1$–$C_2$)

```c
Ahorros() {
  if (C1 o C2) {
    // recibe cuenta de C3
    if (C1) {
      lock()
      x = leerCuenta(v)
      x += cantidad
      escribirCuenta(v, x)
      // envia cuenta a C3
      unlock()
    } else {
      lock()
      x = leerCuenta(v)
      x += cantidad
      escribirCuenta(v, x)
      // envia cuenta a C3
      unlock()
    }
  }
}
```

#### Pseudocódigo (nodo $C_3$–$C_4$)

```c
Ahorros() {
  if (C3 o C4) {
    // recibe cuenta de C1
    if (C3) {
      lock()
      z = leerCuenta(v)
      z += cantidad
      escribirCuenta(v, z)
      // envia cuenta a C1
      unlock()
    } else {
      lock()
      w = leerCuenta(v)
      w += cantidad
      escribirCuenta(v, w)
      // envia cuenta a C1
      unlock()
    }
  }
}
```

#### Paralelización y clasificación de Flynn

Se observa una secuencialización del proceso (no es posible paralelizar), por las barreras de sincronización/comunicación (`lock`/`unlock` y el envío/recibo entre nodos). Esto hace que se ejecute la instrucción de actualización sobre una sola data (SISD, según Flynn).
