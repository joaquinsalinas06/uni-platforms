## Pregunta 1 — Random-Forest (5 puntos)

Las siguientes gráficas muestran métricas de performance de un modelo Random-Forest: tiempo de ejecución, speedup y eficiencia (de izquierda a derecha), para una cantidad de datos de entrenamiento (samples) $N_1=10000$, $N_2=20000$, $N_4=40000$, $N_8=80000$. Los demás parámetros del modelo son iguales en todos los casos. Se realizaron pruebas en el clúster Khipu, hasta 16 procesos MPI. Las curvas de tiempo son casi paralelas entre sí (misma pendiente aproximada) para los distintos $N$; en speedup y eficiencia se sobreponen curvas experimentales (MPI-$N_1,\dots,N_8$) con las curvas teóricas $S\propto p$ y $E\propto 1/\log p$.

#### (a) Comportamiento de la curva de tiempos (1 pt)

**Respuesta:** Las curvas de tiempos son paralelas (pendiente similar), lo que indica un efecto mínimo de comunicación (mayormente cómputo) al incrementar $N$. Esto tiene, como consecuencia, un speedup de los modelos bastante similar entre las distintas cargas de datos, así como la eficiencia.

#### (b) Complejidad $T(n,p)$, speedup y eficiencia — considerando $T_s = O(n)$ (1 pt)

**Respuesta:** Estrictamente $T_s = t\cdot m\cdot n\cdot \log n$, donde $t$ es la cantidad de árboles, $n$ la cantidad de muestras, $m$ el número de características y $\log n$ la profundidad del árbol de decisión (cada árbol se entrena sobre una partición de $n/p$ muestras y las hojas se combinan por votación mayoritaria). Para efectos del ejercicio, $T_s = O(n)$ es suficiente.

Entonces:

$$T_p(n,p) = O\left(\frac{n}{p} + p\left(\alpha + \frac{n}{p}\beta\right) + \log p\left(\alpha + \frac{n}{p}\beta\right)\right)$$

$$S = O\left(\frac{n}{n/p + \log p + n\log p/p + p + n}\right), \qquad E = O\left(\frac{n/p}{n/p + \log p + n\log p/p + p + n}\right)$$

El primer término corresponde al entrenamiento local de los árboles ($n/p$), el segundo a la distribución inicial de datos (scatter lineal $O(p(\alpha+ (n/p)\beta))$), y el tercero a la reducción final por votación mayoritaria ($O(\log p)$ pasos).

#### (c) Escalabilidad fuerte y débil; procesos necesarios para $N=10^6$ (1.5 pts)

**Respuesta:**

**Escalabilidad fuerte** ($n$ = cte):

$$E = O\left(\frac{1}{p\log p + \log p + p^2 + p}\right), \qquad \text{no es escalable}$$

**Escalabilidad débil:**

$$E = O\left(\frac{1}{1 + p\log p/n + \log p/n + p^2/n + p}\right), \qquad \text{escala si } n \propto p^2$$

Aplicando la relación de escalabilidad débil para $E \sim 0{,}8$, se obtiene $p \approx 450$ para $N = 10^6$.

#### (d) Interpretación de las curvas teóricas vs. el experimento (1.5 pts)

**Respuesta:** Las curvas teóricas deben multiplicarse por un factor, ya que en las gráficas se muestran valores absolutos (segundos), mientras que las expresiones de $T(n,p)$ son asintóticas ($O(\cdot)$). El rango de coincidencia entre teoría y experimento está en la región de mayor cantidad de procesos (desde $p=5$ aproximadamente) — para $p$ pequeño el modelo teórico subestima el overhead real de arranque/comunicación. Es posible que cada término (cómputo, scatter, reducción) necesite un factor multiplicativo distinto, ya que agrupan constantes ocultas ($t_c$, $\alpha$, $\beta$) de magnitud diferente.

## Pregunta 2 — Anillo (5 puntos)

#### (a) Comunicación de halo en anillo 1D sin bloqueo mutuo (2.5 pts)

Usando la solución de clase que evita el bloqueo cíclico (los procesos extremos invierten el orden de envío/recepción respecto de los procesos internos), las directivas MPI para comunicar celdas de frontera en un problema de suavizado (stencil de 3 puntos) son:

```cpp
A[1] := smooth(0, 1, 2)
A[n/p] := smooth((n/p-1), (n/p), (n/p+1))
if (j == 0)
    MPI_ISend(A[n/p], 1, MPI_INT, next, t1, MPI_COMM_WORLD, &req);
    MPI_Irecv(A[n/p+1], 1, MPI_INT, next, t2, MPI_COMM_WORLD, &req);
else if (j == p-1)
    MPI_ISend(A[1], 1, MPI_INT, prev, t1, MPI_COMM_WORLD, &req);
    MPI_Irecv(A[0], 1, MPI_INT, prev, t2, MPI_COMM_WORLD, &req);
else {
    MPI_ISend(A[1], 1, MPI_INT, prev, t2, MPI_COMM_WORLD, &req);
    MPI_ISend(A[n/p], 1, MPI_INT, next, t2, MPI_COMM_WORLD, &req);
    MPI_Irecv(A[0], 1, MPI_INT, prev, t1, MPI_COMM_WORLD, &req);
    MPI_Irecv(A[n/p+1], 1, MPI_INT, next, t1, MPI_COMM_WORLD, &req);
    for (i = 2 to n/p-1)
        A[i] := smooth(i-1, i, i+1)
    MPI_Waitall(&req, &status);
}
```

Como la comunicación de las celdas de frontera sucede en paralelo con el cómputo local de las celdas internas (comunicación no bloqueada), la complejidad es:

$$T_{n,p} = O\left(\frac{n}{p} + (\alpha+\beta)\right)$$

#### (b) Análisis de un código de anillo bidireccional (2.5 pts)

El código dado es:

```cpp
for (int i=0; i<1000000; i++) {
  if (rank%2==0) {
    MPI_Recv(rbuf, N, MPI_INT, prev, tag1, MPI_COMM_WORLD, &stats[0]);
    MPI_Send(sbuf, N, MPI_INT, prev, tag2, MPI_COMM_WORLD);
  } else {
    MPI_Send(sbuf, N, MPI_INT, next, tag1, MPI_COMM_WORLD);
    MPI_Recv(rbuf, N, MPI_INT, next, tag2, MPI_COMM_WORLD, &stats[0]);
  }
}
```

**Respuesta:** El código pretende realizar la comunicación de anillo en ambas direcciones un millón de veces. Sin embargo, al escoger los procesos pares/impares que desbloqueen la comunicación (paridad alternante Send/Recv), va a generar una secuencialidad — es la solución "bloqueante" de la pregunta anterior aplicada aquí, pero mal adaptada porque cada proceso sólo intercambia con **un** vecino (`prev` o `next`), no con ambos a la vez, así que no cubre comunicación bidireccional real y encima serializa parejas de rank par/impar en cada ronda.

Para lograr una comunicación de anillo en paralelo (ambas direcciones simultáneas, sin bloqueo mutuo), se desbloquea la comunicación con `Isend`/`Irecv` hacia ambos vecinos a la vez:

```cpp
for (int i=0; i<1000000; i++) {
  MPI_Isend(sbuf, N, MPI_INT, next, t1, MPI_COMM_WORLD, &reqs[0]);
  MPI_Isend(sbuf, N, MPI_INT, prev, t2, MPI_COMM_WORLD, &reqs[1]);
  MPI_Recv(rbuf, N, MPI_INT, prev, t1, MPI_COMM_WORLD, &stats[0]);
  MPI_Recv(rbuf, N, MPI_INT, next, t2, MPI_COMM_WORLD, &stats[1]);
  MPI_Waitall(2, reqs, stats);
}
```

## Pregunta 3 — Cadena binaria (5 puntos)

Paralelizar en forma distribuida, sobre una cadena binaria de 64 bits repartida entre $p$ procesos, la secuencia: (1) imprimir el número binario inicial, (2) pedir un entero $\in[0,63]$ y poner ese bit en 1, (3) imprimir, (4) incrementar el número en binario recorriendo bits de menor a mayor (si el bit es 0 se pone en 1 y termina; si es 1 se pone en 0 y se sigue con el siguiente), (5) imprimir, (6) generar dos subcadenas de 32 bits cada una, (7) hallar su representación decimal.

### Solución

Cada proceso mantiene un `binario_loc` de $64/p$ bits. El diseño combina un proceso raíz (rank 0) que centraliza E/S con comunicación punto a punto y colectivas para distribuir y recolectar el estado global:

```cpp
MPI_Status status;
MPI_Init(&argc, &argv);
MPI_Comm_rank(MPI_COMM_WORLD, &my_rank);
vector<int> binario_loc(64/p, 0);

// (1) imprime valor inicial y (2) asigna el bit pedido
if (my_rank == 0) {
  vector<int> binario(64, 0);
  for (auto bin : binario) cout << bin;
  cout << "numero entero entre 0 y 63: "; cin >> numero;
  int destino = numero / size;
  MPI_Send(&numero, 1, MPI_INT, destino, 1, MPI_COMM_WORLD);
}
if (my_rank == destino) {
  MPI_Recv(&numero, 1, MPI_INT, 0, 1, MPI_COMM_WORLD, &status);
  binario_loc[numero % size] = true;
}
// (3) reconstruye e imprime
MPI_Gather(&binario_loc, 64/size, MPI_INT, &binario, 64/size, MPI_INT, 0, MPI_COMM_WORLD);
if (my_rank == 0) { for (auto bin : binario) cout << bin; }

// (4) incremento en binario, recorriendo de mayor a menor índice local
//     (bit menos significativo = última posición del bloque más "a la derecha")
for (i = size-1; i >= 0; i--) {
  if (binario_loc[i] == 0) { binario_loc[i] = 1; break; }
  else binario_loc[i] = 0;
}
// (5) reconstruye e imprime
MPI_Gather(&binario_loc, 64/size, MPI_INT, &binario, 64/size, MPI_INT, 0, MPI_COMM_WORLD);
if (my_rank == 0) { for (auto bin : binario) cout << bin; }

// (6) divide en dos mitades de 32 bits
vector<int> binario01_loc(32, 0), binario02_loc(32, 0);
MPI_Bcast(binario, 64, MPI_INT, MPI_COMM_WORLD);
if (rank < size/2) {
  for (i = 0; i < 64/size; i++)
    binario01_loc[i] = binario[(64/size)*rank + i];
  MPI_Send(&binario01_loc, 64/size, MPI_INT, 0, 1, MPI_COMM_WORLD);
} else {
  for (i = 0; i < 64/size; i++)
    binario02_loc[i] = binario[(64/size)*rank + i];
  MPI_Send(&binario02_loc, 64/size, MPI_INT, 0, 1, MPI_COMM_WORLD);
}
// (7) recolección y conversión a decimal en el root
if (my_rank == 0) {
  MPI_Recv(&binario01 + rank*(64/size), 64/size, MPI_INT, MPI_ANY_SOURCE, 1, MPI_COMM_WORLD, &status);
  MPI_Recv(&binario02 + rank*(64/size), 64/size, MPI_INT, MPI_ANY_SOURCE, 1, MPI_COMM_WORLD, &status);
  decimal01 = bin_to_dec(binario01_loc);
  decimal02 = bin_to_dec(binario02_loc);
}
MPI_Finalize();
```

Puntos clave del diseño: la distribución inicial no usa `Scatter` porque sólo un dato puntual (`numero`) se envía al proceso dueño de esa posición — un `Send`/`Recv` directo es más barato que difundir. El incremento binario es inherentemente **secuencial dentro de la cadena** (propagación de acarreo de derecha a izquierda), por lo que se resuelve localmente sobre `binario_loc` en cada proceso antes de reconstruir con `Gather`. La partición en dos mitades usa `Bcast` para que todos tengan la cadena completa y cada proceso extraiga su tramo correspondiente a la primera o segunda mitad según su rank.

## Pregunta 4 — Transformada de Fourier (5 puntos)

El cálculo de la transformada de Fourier es de complejidad secuencial $T_s = O(n\log n)$, mientras que la complejidad en paralelo es

$$T_p = O\left(t_c\frac{n}{p}\log(n) + \alpha\log(p) + \beta\frac{n}{p}\log(p)\right)$$

donde $\alpha$ es la latencia, $\beta$ el ancho de banda, y $t_c$ el tiempo de multiplicación/suma que necesita el algoritmo.

#### 4.1 Granularidad (1 pt)

$$G = O\left(\frac{\frac{n}{p}\log(n)}{\log(p)+\frac{n}{p}\log(p)}\right) = O\left(\frac{\log n}{\log p}\right)$$

#### 4.2 Speedup y eficiencia (1 pt)

$$S = O\left(\frac{n\log n}{\frac{n}{p}\log(n)+\log(p)+\frac{n}{p}\log(p)}\right), \qquad E = O\left(\frac{n\log n/p}{\frac{n}{p}\log(n)+\log(p)+\frac{n}{p}\log(p)}\right)$$

#### 4.3 Escalabilidad fuerte y débil (1.5 pts)

**E. Fuerte** ($n$ constante):

$$E = O\left(\frac{1}{p\log p}\right)$$

La eficiencia cae con $p\log p$, por lo que no se considera escalable.

**E. Débil** ($n$, $p$ variables):

$$E = O\left(\frac{1}{\frac{p\log p}{n\log n}+\frac{\log p}{\log n}}\right)$$

Hay dos condiciones de escalabilidad débil, siendo la dominante $p\log p \propto n\log n$.

#### 4.4 Granularidad bajo eficiencia constante (1.5 pts)

Reemplazando la condición de isoeficiencia anterior en la expresión de $E$ se obtiene

$$G = O\left(\frac{p}{n}\right)$$

expresión que es $\ll 1$, ya que $p \ll n$ — es decir, bajo la condición de eficiencia constante la granularidad tiende a ser fina (mucho más cómputo local que comunicación relativa), consistente con que $E$ se mantenga alta.
