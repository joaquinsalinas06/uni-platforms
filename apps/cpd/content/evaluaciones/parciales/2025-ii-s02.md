## Pregunta 1 — N-cuerpos (5 puntos)

Se muestra la gráfica del tiempo de ejecución (horas) vs. número de procesadores $N_p$ para $N=512K$ cuerpos, junto con la función `force` que calcula la nueva posición de cada cuerpo (doble bucle sobre $i,j$: para cada cuerpo $i$ se acumula la aceleración debida a todos los demás $j\ne i$, y se actualizan velocidad y posición). La curva de tiempo total decrece con $p$ hasta un mínimo y luego vuelve a crecer (forma de "U"), producto de la superposición de una curva de cómputo decreciente ($\propto 1/N_p$) y una de comunicación creciente.

#### (a) ¿Qué representa el número óptimo de procesos y cómo determinarlo gráficamente? (1 pt)

**Respuesta:** $p$ óptimo es la cantidad de procesos correspondiente al tiempo mínimo de ejecución. Gráficamente, es la coordenada horizontal que corresponde al valor en el cruce de ambas curvas (la de cómputo, decreciente, y la de comunicación, creciente).

#### (b) Complejidad, speedup y eficiencia para dos modelos de N-cuerpos en paralelo (2 pts)

**Modelo 1) Scatter-Gather:**

$$T_p(n,p) = O\left(\frac{n^2}{p}+p^2\left(\alpha+\frac{n}{p}\beta\right)\right)$$

$$S(n,p) = O\left(\frac{n^2}{\frac{n^2}{p}+p^2(\alpha+\frac{n}{p}\beta)}\right), \qquad E(n,p) = O\left(\frac{n^2/p}{\frac{n^2}{p}+p^2(\alpha+\frac{n}{p}\beta)}\right)$$

**Modelo 2) Broadcast-Reduce:**

$$T_p(n,p) = O\left(\frac{n^2}{p}+\log p(\alpha+n\beta)\right)$$

$$S(n,p) = O\left(\frac{n^2}{\frac{n^2}{p}+\log p(\alpha+n\beta)}\right), \qquad E(n,p) = O\left(\frac{n^2/p}{\frac{n^2}{p}+\log p(\alpha+n\beta)}\right)$$

#### (c) Principio de granularidad para ambos modelos (1 pt)

$$G_1(n,p) = O\left(\frac{\frac{n^2}{p}}{p^2(\alpha+\frac{n}{p}\beta)}\right) = O\left(\frac{n}{p^2}\right), \qquad G_2(n,p) = O\left(\frac{\frac{n^2}{p}}{\log p(\alpha+n\beta)}\right) = O\left(\frac{n}{p\log p}\right)$$

Se observa que, para $n$ constante, el modelo 1) tiene menor granularidad (mayor peso relativo de comunicación), lo que representa una desventaja respecto al modelo 2). En la gráfica se observa el modelo 1), ya que $T_{comm}=O(p)$ describe mejor la curva creciente mostrada; la curva $T_{comm}=O(\log p)$ (caso 2) estaría por debajo de la otra, por lo que el tiempo mínimo sería aún menor que en el caso 1), lo que refuerza la ventaja del modelo 2) sobre el modelo 1).

#### (d) Análisis de escalabilidad para ambos casos (1 pt)

**Caso 1) Scatter-Gather:**

- E. Fuerte ($n$ cte): $E(p) = O\left(\dfrac{1/p}{\frac{1}{p}+p^2(\alpha+\frac{1}{p}\beta)}\right) = O\left(\dfrac{1}{p^3}\right)$ — no escala.
- E. Débil: $E(n,p) = O\left(\dfrac{n^2/p}{\frac{n^2}{p}+p^2(\alpha+\frac{n}{p}\beta)}\right)$ — escala si $n\propto p^2$.

**Caso 2) Broadcast-Reduce:**

- E. Fuerte ($n$ cte): $E(p) = O\left(\dfrac{1/p}{\frac{1}{p}+\log p}\right) = O\left(\dfrac{1}{p\log p}\right)$ — no escala.
- E. Débil: $E(n,p) = O\left(\dfrac{n^2/p}{\frac{n^2}{p}+\log p(\alpha+n\beta)}\right)$ — escala si $n\propto p\log p$.

Por lo tanto, el caso 2 (Broadcast-Reduce) escala mejor (en forma débil), ya que su condición de crecimiento de $n$ es menos exigente que $p^2$.

## Pregunta 2 — Multiplicación Matriz-Vector (5 puntos)

Se resuelve $y=Ax$ con $A$ de banda, semiancho $k=5$ (cada fila tiene hasta 5 vecinos a la izquierda y 5 a la derecha, salvo cerca de los bordes).

#### (a) Particionamiento por bloques de filas y comunicación bloqueada (2.5 pts)

```
Algoritmo: PRAM (MPI bloqueante) para y = Ax, A de banda, semiancho k=5
Entrada: en P0, A ∈ R^{n×n} de banda (A_ij ≠ 0 sólo si |i-j| ≤ k), x[1..n], p procesos, n mod p = 0
Salida: en P0, y = Ax

n_loc ← n/p
Cada proceso P_r computa filas globales i ∈ {r·n_loc+1, ..., (r+1)·n_loc}

MPI_Scatter(A, n_loc×n, ROWBLOCK, A_loc, root=P0)
MPI_Scatter(x, n_loc, DOUBLE, x_loc, root=P0)

// Intercambio de halos (k=5 elementos por lado), vecinos left=r-1, right=r+1
if left existe:
    MPI_Sendrecv(&x_loc[1] (enviar k elem a left), &x_halo_L[1..k] (recibir de left))
if right existe:
    MPI_Sendrecv(&x_loc[n_loc-k+1] (enviar k elem a right), &x_halo_R[1..k] (recibir de right))
// Si un vecino no existe (borde global), se omite la llamada y los halos faltantes valen 0

// Producto banda y_loc = A_loc·x (usando x_loc y los halos según corresponda)
for i ← 1 to n_loc:
    y_loc[i] ← 0
    for δ ← -k to k:
        j ← i + δ
        si 1 ≤ j ≤ n_loc:          y_loc[i] += A[i][j]·x_loc[j]
        si j < 1 y left existe:     y_loc[i] += A[i][j]·x_halo_L[k-(i-j)]
        si j > n_loc y right existe: y_loc[i] += A[i][j]·x_halo_R[j-n_loc]
        si no: contribución nula (borde global)

MPI_Gather(y_loc, n_loc, DOUBLE, y, root=P0)
```

#### (b) Optimización con comunicación no bloqueada (2.5 pts)

Se propone usar `Isend`/`Irecv` en vez de `Sendrecv`, así como `Iscatter`/`Igather`. El cómputo local se separa en dos: uno **interno**, que calcula las celdas que no dependen de la comunicación de frontera y se realiza mientras la comunicación de los halos se ejecuta en segundo plano; y uno de **frontera**, que se completa después de un `MPI_Waitall()`, momento en que se garantiza que ya llegaron los halos necesarios para las primeras y últimas $k$ filas del bloque local.

## Pregunta 3 — Bisección (5 puntos)

Se busca la raíz de $f(x)=0$ en $[a,b]$ con $f(a)\cdot f(b)<0$, usando el método de bisección secuencial que en cada iteración divide el intervalo a la mitad y conserva la mitad con cambio de signo.

#### (a) Paralelización con comunicación colectiva (2.5 pts)

En lugar de bisecar en 2, se divide el intervalo $[a,b]$ en $p$ subintervalos iguales (uno por proceso), cada proceso evalúa el signo en los extremos de su subintervalo, y se usa una reducción lógica para encontrar cuál subintervalo tiene el cambio de signo:

```
Función raiz_biseccion_MPI(f, a, b, ε, maxit, p):
  rank ← ID del proceso
  for k ← 1 to maxit:
    subint ← (b-a)/p
    myleft ← a + rank·subint
    myright ← myleft + subint
    f_L ← f(myleft); f_R ← f(myright)
    si f_L·f_R < 0:
      local_found ← 1; a_new ← myleft; b_new ← myright
    si no:
      local_found ← 0

    MPI_Allreduce(local_found, found, MPI_LOR)
    si found = 1:
      MPI_Bcast(a_new, 1, DOUBLE, root)
      MPI_Bcast(b_new, 1, DOUBLE, root)
      a ← a_new; b ← b_new

    si |b-a| < ε:
      MPI_Bcast(a, 1, DOUBLE, root)
      return a   // tolerancia alcanzada
  return (a+b)/2  // máx. iteraciones alcanzado
```

Al dividir en $p$ subintervalos por iteración en vez de 2, la convergencia es $p$ veces más rápida en número de iteraciones (reduce el intervalo en un factor $p$ por ronda en vez de 2), a costa de $O(p)$ evaluaciones de $f$ y una colectiva de reducción/broadcast por ronda.

#### (b) Optimización de la solución (2.5 pts)

Se propone usar comunicación no bloqueante como `MPI_Iallreduce(&in, &out, 1, MPI_LONG_LONG_INT, MPI_MINLOC, MPI_COMM_WORLD)`. Como todos los procesos conocen $a$, $b$ y `subint`, basta con difundir el **índice** del proceso ganador (el que encontró el cambio de signo) en vez de los valores completos de $a_{new}$, $b_{new}$; cada proceso recalcula localmente los nuevos límites a partir de ese índice, ahorrando el ancho de banda de los dos `Bcast` de punto flotante por dos `Bcast` (o un `Allreduce` con `MINLOC`) de un entero, y solapando la reducción con trabajo útil si se reorganiza el bucle.

## Pregunta 4 — Broadcast (5 puntos)

Se optimiza la comunicación colectiva (broadcast) con tres modelos, aplicados a un algoritmo de complejidad secuencial $O(n^2)$:

- **Binomial:** $T_p(n,p) = O(\log p\,(n\alpha+\beta))$
- **Pipeline lineal:** $T_p(n,p) = O(n\alpha+p\beta)$
- **Binary Tree Pipelined:** $T_p(n,p) = O(\log p\,\alpha+n\beta)$

#### 4.1 Escalabilidad de cada caso (2 pts)

**Caso 1 (Binomial):** $T_p(n,p)=O\left(\dfrac{n^2}{p}+\log p(n\alpha+\beta)\right)$, $E(n,p)=O\left(\dfrac{n^2/p}{\frac{n^2}{p}+\log p(n\alpha+\beta)}\right)$

- E. Fuerte: $E_p(p)=O\left(\dfrac{1}{p\log p}\right)$, no escala.
- E. Débil: escala si $n\propto p\log p$.

**Caso 2 (Pipeline lineal):** $T_p(n,p)=O\left(\dfrac{n^2}{p}+n\alpha+p\beta\right)$, $E(n,p)=O\left(\dfrac{n^2/p}{\frac{n^2}{p}+n\alpha+p\beta}\right)$

- E. Fuerte: $E_p(p)=O\left(\dfrac{1}{p^2}\right)$, no escala.
- E. Débil: escala si $n\propto p$.

**Caso 3 (Binary Tree Pipelined):** $T_p(n,p)=O\left(\dfrac{n^2}{p}+\log p\,\alpha+n\beta\right)$, $E(n,p)=O\left(\dfrac{n^2/p}{\frac{n^2}{p}+\log p\,\alpha+n\beta}\right)$

- E. Fuerte: $E_p(p)=O\left(\dfrac{1}{p\log p}\right)$, no escala.
- E. Débil: escala si $n\propto p$.

#### 4.2 Cantidad óptima de procesos, minimizando $T_p(n,p)$ (1.5 pts)

Resolviendo $\partial T_p(n,p)/\partial p = 0$ en cada caso:

- Caso 1: $p\propto n$
- Caso 2: $p\propto n$
- Caso 3: $p\propto n^2$ — esta relación permite escalar al máximo mientras el tiempo sigue cayendo.

#### 4.3 Granularidad — ¿confirman estas métricas el mejor método? (1.5 pts)

$$G_1=\frac{n^2}{n\cdot p\log p}, \quad \text{menor granularidad (fina)} \qquad G_2=\frac{n^2}{np+p^2}, \quad \text{mayor granularidad (gruesa)} \qquad G_3=\frac{n^2}{p\log p+np}, \quad \text{granularidad intermedia}$$

El caso 3 (Binary Tree Pipelined) permite escalar al máximo mientras el tiempo sigue cayendo, a la vez que muestra un equilibrio en la relación cómputo-comunicación (granularidad intermedia) — combina el bajo costo de latencia del árbol binomial ($\log p$) con el buen aprovechamiento de ancho de banda del pipeline, por lo que resulta el mejor de los tres métodos para este algoritmo.
